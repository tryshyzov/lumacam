# LumaLink Studio

<p align="center"><img src="assets/LumaCam.png" alt="LumaLink Studio logo" width="240"></p>

Прототип приложения для Windows, использующего Android-смартфон в качестве камеры. Приложение для iOS и установочный файл пока не реализованы. (Полностью вайбкодинг.) 

## Запуск на ПК
Необходим Python 3.10+ и все пакеты из `requirements.txt` (интерфейс написан на PySide6 — Qt для Python):

```powershell
python -m pip install -r requirements.txt
python main.py
```

Запуск моделей тестирования с помощью:

```powershell
python -m unittest discover -s tests -v
```

## Сборка .exe файла на Windows

На Windows, установите PyInstaller и соберите исполняемый файл:

```powershell
python -m pip install -r requirements.txt pyinstaller
python -m PyInstaller --noconfirm --clean LumaLinkStudio.spec
```

Исполняемый файл записывается в `dist\LumaLinkStudio.exe`.

## Сборка Windows инсталлятора

Установи Inno Setup 6 и чтобы собрать исполняемый файл для рабочего стола. Из корневой папки проекта выполни команду:

```powershell
& "$env:LOCALAPPDATA\Programs\Inno Setup 6\ISCC.exe" installer\LumaLinkStudio.iss
```

Установочный пакет записывается в `dist\installer`. Сначала соберите виртуальную камеру (см. [`virtualcam/README.md`](./virtualcam/README.md)): установщик включает её в себя и регистрирует. Он один раз запрашивает права администратора, потому что камера, видимая всем программам, регистрируется для всего компьютера. Драйвер ядра не устанавливается. Текущие исполняемые файлы не подписаны и являются сборками для разработки. Подробнее в [`installer/README.md`](./installer/README.md).

## Сборка приложения для macOS

На macOS 13 или новее, с Python 3.10+, установите зависимости и PyInstaller, затем из корневой папки проекта запустите скрипт сборки:

```sh
python3 -m pip install -r requirements.txt pyinstaller
scripts/build-macos.sh
```

Скрипт создаёт `dist/LumaLink Studio.app` и `dist/LumaLinkStudio-<версия>-macos.dmg`. Приложение подписано без Developer ID, поэтому на другом Mac в первый раз откройте его через правый клик → **Открыть**. При первом запуске macOS спросит, разрешить ли находить устройства в локальных сетях: разрешите, иначе телефон не подключится. Своя виртуальная камера LumaLink Camera пока есть только для Windows: на macOS виртуальная камера работает через OBS Virtual Camera (OBS Studio 30+, один раз запущенную из OBS).

## Подключение Android камеры

Модуль `android-app` — это нативный компаньон для Kotlin/CameraX. Он отображает предварительный просмотр изображения с камеры и передает аппаратно закодированные блоки доступа H.264 на рабочий стол без кода доступа. USB использует двоичный протокол с префиксом длины, подтверждение для каждого кадра и сообщения управления камерой через сеть USB-модема телефона; Wi-Fi использует ту же видео/управляющую кадрировку через TCP-соединение. Отладка по USB нужна только для запасного пути при включённом VPN (см. ниже).

Для установки .apk можно использовать adb (Смотреть ниже), а так же можно просто скачать самому из `Releases`:

```powershell
adb install -r android-app\build\outputs\apk\debug\app-debug.apk
adb shell am start -n com.lumalink.companion/.MainActivity
```

1. Найдите **LumaLink Companion** на телефоне и откройте.
2. Для **USB**, подключите кабель и включите на телефоне **USB-модем** (Точка доступа и модем). Выберите **USB** в приложении на телефоне и нажмите **Начать трансляцию**, затем выберите USB в **LumaLink Studio** и нажмите **Подключить камеру**. Компьютер сам найдёт телефон в сети USB-модема. Пока модем включён, Windows может направлять интернет через мобильные данные телефона.

   **Если на компьютере включён VPN.** VPN с блокировкой локальной сети (kill switch) не пропускает трафик к телефону, и обойти это из приложения нельзя. Если телефон не найден за 3 секунды, программа переключается на `adb forward`, который идёт напрямую по USB и VPN не затрагивается. Для этого на телефоне нужно включить **Отладку по USB**; `adb.exe` уже встроен в приложение. У режима Wi-Fi такого запасного пути нет — добавьте LumaLink Studio в исключения VPN (раздельное туннелирование).
3. Для **Wi-Fi**, в **LumaLink Studio** выберите Wi-Fi и нажмите **Подключить камеру**, чтобы компьютер начал ожидать подключение. Затем в **LumaLink Companion** выберите **Wi-Fi** и нажмите **Начать трансляцию**: телефон сам найдёт компьютер в сети. Если не найдёт, впишите в приложении на телефоне IP, показанный в **LumaLink Studio**. Оба устройства должны находиться в одной доверенной сети; брандмауэр Windows может запросить разрешение на использование настольного приложения в частных сетях.
4. Stop the stream from either app when finished. There is no access code or encryption: any device that can reach the desktop on port 8765 can view the camera stream. Use Wi-Fi only on a trusted private network and stop streaming when not needed.

Предварительный просмотр на рабочем столе и прямая трансляция с камеры Android используют блоки доступа H.264 с префиксом длины через USB-модем или Wi-Fi. Android кодирует с помощью MediaCodec; Windows декодирует с помощью PyAV и корректирует ориентацию потока на 180 градусов перед отображением или пересылкой кадров. Каждый блок доступа подтверждается перед отправкой следующего, и транспорт сохраняет только последний ожидающий блок доступа, чтобы ограничить задержку в очереди. На рабочем столе можно запросить вывод анализа в разрешении 480p, 720p или 1080p и изменить фокус/автофокус, экспозицию, ISO, баланс белого, фронтальную/заднюю камеру, зум и целевую частоту кадров. Приложение для Android применяет поддерживаемые элементы управления через Camera2 и ограничивает неподдерживаемые настройки диапазонами возможностей устройства; фактическое разрешение и частота потока могут быть ниже запрошенных на устройствах с ограниченными режимами камеры или производительностью обработки.

### Windows virtual camera

В LumaLink Studio есть собственная виртуальная камера — **LumaLink Camera**. Это DirectShow-фильтр пользовательского режима (исходники в [`virtualcam/`](./virtualcam/)), а не драйвер ядра, поэтому подпись драйвера, тестовый режим и изменения Secure Boot не нужны. Камеру регистрирует установщик; после этого она появляется в списке камер в Zoom, Discord, Telegram, браузерах и OBS в Windows 10 и 11, и ставить больше ничего не нужно. Пока видео не передаётся, камера показывает заставку — значок камеры на сером фоне.

Нулевая задержка невозможна: экспозиция камеры, кодирование, передача, декодирование и отображение на рабочем столе — каждый из этих факторов вносит задержку.

## Архитектура продукта

```text
Android companion (Kotlin / Camera2, CameraX) ─── session + video/control channel
                                                                    │
Planned iOS companion (Swift / AVFoundation) ──────────────────────┘
                                                                   ▼
                                              Windows desktop app (Python prototype)
                                                ├─ preview and settings UI
                                                ├─ USB / Wi-Fi transport adapters
                                                └─ LumaLink Camera (DirectShow)
                                                     │
                         Discord · Telegram · OBS · Zoom · Google Meet
```

LumaLink Camera устанавливается установщиком LumaLink Studio; драйвер ядра не используется.

### ПК (Windows)

- Текущий прототип объединяет пользовательский интерфейс, подключение, декодирование и доставку кадров в одном приложении на Python; отдельная служба сессий — это задача на будущее.
- Кадры отправляются в LumaLink Camera. Если она не установлена (запуск из исходников или отдельного exe), используется OBS Virtual Camera, затем Unity Capture через `pyvirtualcam`. Физическая камера никогда не используется как запасной вариант.
- LumaLink не устанавливает, не регистрирует, не обновляет и не удаляет сторонние устройства камер.

### Мобильный компаньон

- Android: реализовано на Kotlin с использованием элементов управления CameraX/Camera2. Возможности устройств различаются; этот прототип пока не предоставляет полную карту возможностей в настольный интерфейс.
- iOS: не реализовано. В будущем в качестве дополнения к Swift/AVFoundation необходимо будет запрашивать у каждого устройства/формата поддерживаемые диапазоны фокусировки, экспозиции, баланса белого, объектива, зума и частоты кадров, прежде чем отображать элементы управления.
- Оба клиента согласовывают только те возможности, которые фактически поддерживаются выбранной камерой. Неподдерживаемые элементы управления остаются недоступными, а не сообщают об успешном завершении.

### Работа

- Текущий прототип отправляет видео H.264 без аутентификации или шифрования по локальной сети Wi-Fi. Для USB компьютер находит телефон в сети USB-модема и подключается к его TCP-порту (при блокировке сети VPN — через `adb forward`); оба способа передачи используют блоки доступа H.264 с префиксом длины, подтверждения для каждого кадра и канал управления. Доступ по USB зависит от авторизованного отладочного соединения ADB пользователя.
- LumaLink Camera — DirectShow-фильтр на основе Unity Capture. OBS Virtual Camera и Unity Capture остаются только запасными вариантами для запуска без установщика.
- В производственной среде для передачи видео и управляющих сообщений можно использовать аутентифицированную сессию WebRTC. Выбор способа передачи следует разделять от кодирования и протокола управления камерой.
- Проверяйте задержку, поведение повторного подключения и сетевые разрешения независимо на Android и iOS. Не следует предполагать, что режим USB-камеры или USB-модем доступны на каждой комбинации телефона/ОС.

### Совместимость и ограничения

- Виртуальная камера зависит от установленного в Windows бэкэнда камеры; предварительный просмотр сам по себе не регистрирует устройство камеры в масштабах всей системы.
- Элементы управления камерой и доступные объективы зависят от телефона, выбранного объектива, формата камеры и API операционной системы. В частности, приложение не должно гарантировать ручную настройку ISO, фокусировки или баланса белого, если устройство их не предоставляет.
- Совместимость следует проверять для каждого целевого приложения и версии Windows; некоторые видеоклиенты отображают камеры только при запуске.

## Этапы реализации

1. Оболочка рабочего стола Windows, модели совместного использования сессий/управления и пользовательский интерфейс с учетом возможностей.
2. Приложение для Android с аппаратным кодированием H.264 и кадрированием USB/Wi-Fi с ограничением по актуальности через USB-модем или локальную сеть.
3. Вывод изображения через собственную виртуальную камеру LumaLink Camera.
4. Улучшенная поддержка USB-транспорта и проверка задержки/переподключения Wi-Fi.
5. Приложение для iOS, сопоставление возможностей и совместимость с USB/Wi-Fi.
6. Установщик/подпись, тестирование совместимости и сквозная матрица устройств.
