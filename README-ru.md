# LumaLink Studio

<p align="center"><img src="assets/LumaCam.png" alt="LumaLink Studio logo" width="240"></p>

Прототип приложения для Windows, использующего Android-смартфон в качестве камеры. Приложение для iOS и установочный файл пока не реализованы. (Полностью вайбкодинг.) 

## Запуск на ПК
Необходим Python 3.10+ с Tkinter и все пакеты из `requirements.txt`:

```powershell
python -m pip install -r requirements.txt
python main.py
```

Запуск моделей тестирования с помощью:

```powershell
python -m unittest discover -s tests -v
```

## Сборка .exe файла на Windows

На Windows, установите PyInstaller и соберите исполняемый файл:

```powershell
python -m pip install -r requirements.txt pyinstaller
python -m PyInstaller --noconfirm --clean LumaLinkStudio.spec
```

Исполняемый файл записывается в `dist\LumaLinkStudio.exe`.

## Сборка Windows инсталлятора

Установи Inno Setup 6 и чтобы собрать исполняемый файл для рабочего стола. Из корневой папки проекта выполни команду:

```powershell
& "$env:LOCALAPPDATA\Programs\Inno Setup 6\ISCC.exe" installer\LumaLinkStudio.iss
```

Установочный пакет записывается в `dist\installer`. Он устанавливает настольное приложение без прав администратора или драйвера ядра LumaLink. Для вывода изображения с виртуальной камеры требуется OBS Studio с OBS Virtual Camera или отдельно установленный бэкенд Unity Capture. Текущие исполняемые файлы для настольного приложения и установки являются неподписанными артефактами разработки, а не общедоступными бинарными файлами. Подробности см. в [`installer/README.md`](./installer/README.md).

## Подключение Android камеры

Модуль `android-app` — это нативный компаньон для Kotlin/CameraX. Он отображает предварительный просмотр изображения с камеры и передает аппаратно закодированные блоки доступа H.264 на рабочий стол без кода доступа. USB использует двоичный протокол с префиксом длины, подтверждение для каждого кадра и сообщения управления камерой через пересылку ADB; Wi-Fi использует ту же видео/управляющую кадрировку через TCP-соединение. (`android-app` отсутствует из за квоты Github на отправку файлов)

Для установки .apk можно использовать adb (Смотреть ниже), а так же можно просто скачать самому из `Releases`:

```powershell
adb install -r android-app\build\outputs\apk\debug\app-debug.apk
adb shell am start -n com.lumalink.companion/.MainActivity
```

1. Найдите **LumaLink Companion** на телефоне и откройте.
2. Для **USB**, впишите в адрес телефона `127.0.0.1`, и нажмите **Начать трансляцию**, выберите в **LumaLink Studio** и нажмите **Подключить камеру**. Программа настроена на `adb forward` через авторизованную отладку по USB.
3. Для **Wi-Fi**, в **LumaLink Studio** выберите Wi-Fi и посмотрите на IP вашего компьютера. Впишите этот IP в приложении **LumaLink Companion**, нажмите **Начать трансляцию**, на ПК нажмите **Подключить камеру** в **LumaLink Studio**. Оба устройства должны находиться в одной доверенной сети; брандмауэр Windows может запросить разрешение на использование настольного приложения в частных сетях.
4. Stop the stream from either app when finished. There is no access code or encryption: any device that can reach the desktop on port 8765 can view the camera stream. Use Wi-Fi only on a trusted private network and stop streaming when not needed.

Предварительный просмотр на рабочем столе и прямая трансляция с камеры Android используют блоки доступа H.264 с префиксом длины через переадресацию USB ADB или Wi-Fi. Android кодирует с помощью MediaCodec; Windows декодирует с помощью PyAV и корректирует ориентацию потока на 180 градусов перед отображением или пересылкой кадров. Каждый блок доступа подтверждается перед отправкой следующего, и транспорт сохраняет только последний ожидающий блок доступа, чтобы ограничить задержку в очереди. На рабочем столе можно запросить вывод анализа в разрешении 480p, 720p или 1080p и изменить фокус/автофокус, экспозицию, ISO, баланс белого, фронтальную/заднюю камеру, зум и целевую частоту кадров. Приложение для Android применяет поддерживаемые элементы управления через Camera2 и ограничивает неподдерживаемые настройки диапазонами возможностей устройства; фактическое разрешение и частота потока могут быть ниже запрошенных на устройствах с ограниченными режимами камеры или производительностью обработки.

### Windows virtual camera

LumaLink **не** устанавливает и не использует свой пользовательский драйвер ядра AVStream. В Windows 10 и 11 настольное приложение сначала пытается использовать отдельно установленную **OBS Virtual Camera**, а затем **Unity Video Capture**. Если ни один из бэкендов не установлен и не работает, приложение отображает ошибку с указанием необходимых бэкендов. Перед запуском виртуального вывода установите OBS Studio (включая компонент виртуальной камеры) или Unity Capture.

Нулевая задержка невозможна: экспозиция камеры, кодирование, передача, декодирование и отображение на рабочем столе — каждый из этих факторов вносит задержку.

## Архитектура продукта

```text
Android companion (Kotlin / Camera2, CameraX) ─── session + video/control channel
                                                                    │
Planned iOS companion (Swift / AVFoundation) ──────────────────────┘
                                                                   ▼
                                              Windows desktop app (Python prototype)
                                                ├─ preview and settings UI
                                                ├─ USB / Wi-Fi transport adapters
                                                └─ OBS Virtual Camera / Unity Capture
                                                     │
                         Discord · Telegram · OBS · Zoom · Google Meet
```

Для установки OBS Virtual Camera или Unity Capture необходимо использовать отдельную программу; LumaLink не устанавливает драйверы для камер.

### ПК (Windows)

- Текущий прототип объединяет пользовательский интерфейс, подключение, декодирование и доставку кадров в одном приложении на Python; отдельная служба сессий — это задача на будущее.
- Отправка кадров осуществляется через бэкенд OBS `pyvirtualcam`, с последующим использованием Unity Capture. Никогда не используется физическая камера.
- LumaLink не устанавливает, не регистрирует, не обновляет и не удаляет сторонние устройства камер.

### Мобильный компаньон

- Android: реализовано на Kotlin с использованием элементов управления CameraX/Camera2. Возможности устройств различаются; этот прототип пока не предоставляет полную карту возможностей в настольный интерфейс.
- iOS: не реализовано. В будущем в качестве дополнения к Swift/AVFoundation необходимо будет запрашивать у каждого устройства/формата поддерживаемые диапазоны фокусировки, экспозиции, баланса белого, объектива, зума и частоты кадров, прежде чем отображать элементы управления.
- Оба клиента согласовывают только те возможности, которые фактически поддерживаются выбранной камерой. Неподдерживаемые элементы управления остаются недоступными, а не сообщают об успешном завершении.

### Работа

- Текущий прототип отправляет видео H.264 без аутентификации или шифрования по локальной сети Wi-Fi. Для USB ADB перенаправляет TCP-соединение с рабочего стола на абстрактный локальный сокет Android; оба способа передачи используют блоки доступа H.264 с префиксом длины, подтверждения для каждого кадра и канал управления. Доступ по USB зависит от авторизованного отладочного соединения ADB пользователя.
- OBS Virtual Camera и Unity Capture — это сторонние бэкэнды для камер Windows, которые необходимо устанавливать отдельно. LumaLink использует OBS в первую очередь и Unity в качестве резервного варианта как в Windows 10, так и в Windows 11.
- В производственной среде для передачи видео и управляющих сообщений можно использовать аутентифицированную сессию WebRTC. Выбор способа передачи следует разделять от кодирования и протокола управления камерой.
- Проверяйте задержку, поведение повторного подключения и сетевые разрешения независимо на Android и iOS. Не следует предполагать, что режим USB-камеры или USB-модем доступны на каждой комбинации телефона/ОС.

### Совместимость и ограничения

- Виртуальная камера зависит от установленного в Windows бэкэнда камеры; предварительный просмотр сам по себе не регистрирует устройство камеры в масштабах всей системы.
- Элементы управления камерой и доступные объективы зависят от телефона, выбранного объектива, формата камеры и API операционной системы. В частности, приложение не должно гарантировать ручную настройку ISO, фокусировки или баланса белого, если устройство их не предоставляет.
- Совместимость следует проверять для каждого целевого приложения и версии Windows; некоторые видеоклиенты отображают камеры только при запуске.

## Этапы реализации

1. Оболочка рабочего стола Windows, модели совместного использования сессий/управления и пользовательский интерфейс с учетом возможностей.
2. Приложение для Android с аппаратным кодированием H.264 и кадрированием USB/Wi-Fi с ограничением по актуальности через переадресацию ADB или локальную сеть.
3. Вывод изображения с виртуальной камеры Windows через отдельно установленные OBS Virtual Camera или Unity Capture.
4. Улучшенная поддержка USB-транспорта и проверка задержки/переподключения Wi-Fi.
5. Приложение для iOS, сопоставление возможностей и совместимость с USB/Wi-Fi.
6. Установщик/подпись, тестирование совместимости и сквозная матрица устройств.
